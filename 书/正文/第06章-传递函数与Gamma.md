# 第 06 章 传递函数与 Gamma：从 CRT 到 sRGB

前面两章聊的是"颜色在哪里"（色度图）和"能显示多宽"（色域）。这一章换一个维度：**同样的颜色，像素值和真实亮度到底是什么关系？** 很多人一辈子都以为"像素值 128 就等于亮度 128"，其实完全不是。搞懂这条"码值↔光"的换算规则（也就是传递函数和 Gamma），你才算真正明白 SDR 是怎么被"约定"出来的，也才能理解 HDR 为什么要换一套新规则。

## 6.1 核心误会：像素值不是光

先做个思想实验。一张 8 位灰度图里，码值 0 表示最黑，255 表示最白，128 表示"中间"。那么码值 128 的像素，亮度是不是 255 的一半？

**不是。** 它对应的光大约是最大亮度的 **百分之二十几**，而不是 50%。这不是显示器坏了，而是行业约定好的：**码值和实际亮度之间不是直线关系，而是一条弯的曲线。**

这条"码值 ↔ 光"的换算曲线，就是**传递函数（transfer function）**。它是整个显示世界最容易被忽略、又最影响观感的一环。

![图 06-1　Gamma 2.2 曲线 vs 线性：码值 128 只对应约两成多的光](图片/06/f1_gamma_curve.png)

## 6.2 两条曲线：OETF 与 EOTF

传递函数其实有**两个方向**，方向搞反是初学者最常犯的错误。请务必分清楚：

| 名称 | 全称 | 方向 | 用在哪 |
|---|---|---|---|
| **OETF** | 光电转换函数（Opto-Electronic Transfer Function） | **光 → 码值** | 采集/编码端（相机、母版） |
| **EOTF** | 电光转换函数（Electro-Optical Transfer Function） | **码值 → 光** | 显示端（屏幕） |

记忆口诀：**OETF 把光"打包"成码值，EOTF 把码值"解包"成光。**

OETF 与 EOTF 的转换规则在最早期源于 CRT 的物理特性，这是电子枪和荧光粉的物理特性决定的。 到了现代，之所以这对转换关系还要保留的原因，主要是编码位深带来的。LCD/OLED 的物理特性与 CRT 完全不同，现在的 OETF/EOTF 是人为规定的标准，用于兼容历史、优化感知、节省位深。在前面已经介绍过，为了能够给暗部区域多分配一些 bit位，这种映射关系被保留了下来；这也使得一些很老的彩色影片依然可以直接在很新的LCD屏幕上播放。后面的两小节我们会重点介绍。

```mermaid
graph LR
  A["场景的光"] -->|OETF 打包| B["码值 / 信号"]
  B -->|EOTF 解包| C["屏幕上重现的光"]
```

理论上，只要显示端的 EOTF 正好是编码端 OETF 的**逆运算**，最后的光就和原来一致，"画面就对了"。但现实中这两条曲线并不是严格互逆——这正是各种"颜色不一致"的根源之一。

这里有个容易绕晕的点：在 SDR 体系里，**业界习惯用"显示端的曲线"（EOTF）来当基准，编码时取它的反函数**。所以你会看到 sRGB 标准里定义的是 EOTF，而 BT.709 标准里定义的是 OETF；名字不同，说的其实是链路的两头。

![图 06-3　采集 OETF → 传输 → 显示 EOTF 的完整链路：两头必须互逆](图片/06/f3_oetf_eotf.png)

## 6.3 Gamma 的起源：CRT 的"先天非线性"

为什么当初要设计成弯曲的曲线，而不是简单的一条直线？故事要回到显像管电视（CRT）时代。

老式 CRT 靠电子枪轰击屏幕发光。它的**输入电压和输出亮度之间天生不是直线**，而近似一条幂函数：

```text
亮度 L ∝ 电压 V^γ ，  其中 γ(伽马) 约 2.2
```

也就是说，电压只加到一半，亮度并不是一半，而只有大约 (0.5)^2.2 ≈ 0.22，也就是两成多。这个指数 γ（**伽马**）就是"Gamma"一词的来历。

当年工程师发现这个特性后，做了一个"顺水推舟"的处理：**既然显示器天生是 2.2 次方，那我就在信号编码时用 1/2.2 次方（约 0.45）预先"反向弯曲"一次**，两端一抵消，总体就恢复成直线了。

**所以 Gamma 编码本质上是一个历史副产品**——它不是为了让画面更好看而精心设计的，而是为了迁就 CRT 的怪脾气。但它意外带来一个巨大好处，见下一节。

## 6.4 为什么非线性编码反而更省位深

假设没有 Gamma，直接用直线（线性）编码：码值 128 对应一半亮度。听起来很合理，但会出事。

还记得第 3 章的结论吗——**人眼对暗部变化远比亮部敏感**。在线性编码下，亮部占了大量码值却看不出差别（浪费），暗部码值稀少却被量化得极粗糙（出现**色带（banding）**，也就是本该平滑的渐变变成一圈圈台阶）。

Gamma 编码恰好反过来：**把更多码值分配给人眼敏感的暗部，把少一些分给人眼不敏感的亮部。** 于是同样 8 位精度，暗部就细腻多了。

打个比方：**Gamma 编码就像一个"压缩包"**。它知道哪段信息重要（暗部），就多分点空间；哪段不重要（高光），就少分点。这正是"感知编码"思想的雏形——后来 HDR 的 PQ 曲线（见第 7 章）把这个思路推到了极致。

| 编码方式 | 暗部码值分配 | 8 位下暗部表现 |
|---|---|---|
| 线性 | 很少 | 色带明显、发灰 |
| Gamma（约 2.2） | 多 | 大致平滑，肉眼看不出台阶 |

![图 06-5　非线性编码为何省位深：码值优先分给暗部，暗部台阶更密](图片/06/f5_why_nonlinear.png)

### XYZ 与 RGB

我们回到 XYZ 和 RGB，来更深入地讲解一下这里面的关系。

sRGB 相当于在 XYZ 可见色域里选了一个由三个正原色构成的三角形。三角形内的颜色可以用非负 sRGB 码值表示；三角形外、也就是 sRGB 色域外的颜色，sRGB 不涉及，强行表示会出现负分量或超 1 分量。这跟“最原始三刺激值有负值”有关，但不是 sRGB 直接避开了 XYZ 的负值，而是 sRGB 用正原色定义了一个有限的、物理可实现的色域子集。

我们需要明确的是，sRGB选择的三基色并不是先前色彩混合实验中选择的CIE RGB三基色，CIE RGB三基色只是为了探索不同波长的光跟三基色之间的关系，这不要搞混。

XYZ 是线性的，8bit 在暗部精度很差，容易看到明显色带，所以如果要存储 XYZ，常用浮点 TIFF、EXR、DPX 等。sRGB 是 XYZ 的一个子集映射， sRGB 能表示的颜色都在 XYZ 里，但 XYZ 能表示的颜色远多于 sRGB。Gamma 编码是为了存储效率，sRGB 的 Gamma 曲线让码值分配更符合人眼，所以 8bit sRGB 看起来比 8bit 线性 RGB 好得多。

图像经常会用jpg、PNG等格式编码。以 PNG 文件为例，存储的不一定天生就是 sRGB。它可能：
- 带 sRGB chunk：明确表示按 sRGB 解释；
- 带 ICC profile：按嵌入的 ICC 解释，可能是 Adobe RGB、Display P3 等；
- 什么都没有：很多软件会默认当 sRGB，但严格说色彩含义未定义。
用不同图片查看器打开同一张图可能会显示不同的色调，这是正常现象，需要分析查看器采用的是什么映射方法。



## 6.5 sRGB 的分段 EOTF：不止是一条幂函数

说了半天"约 2.2"，但 sRGB 标准里写的其实是一条**分段曲线**，因为纯幂函数在最黑处（码值 0 附近）斜率趋向无穷，数值上不好处理。

sRGB 的显示 EOTF（把码值 V（0～1）换成线性亮度 L）是这样定义的：

```text
若 V ≤ 0.04045:   L = V / 12.92
否则:             L = ((V + 0.055) / 1.055) ^ 2.4
```

解读一下：**暗部用一条直线**（斜率 12.92，接近线性），**亮部用 2.4 次方**。虽然是 2.4 次方，但因为暗部那段被"掰直"了，**整条曲线合起来的等效效果大约就是 2.2**。所以大家口语里常说"sRGB 的 gamma 是 2.2"，严格说是"分段曲线，整体约 2.2"。

![图 06-2　sRGB 的分段 EOTF：暗部走直线、亮部约 2.4 次方](图片/06/f2_srgb_piecewise.png)

## 6.6 BT.709 的 OETF：电视那边怎么写

高清电视（BT.709）定义的是编码端的 OETF，把线性光 L 转成信号 V：

```text
若 L < 0.018:   V = 4.5 × L
否则:           V = 1.099 × L^0.45 − 0.099
```

注意这里的指数 **0.45 ≈ 1/2.2**，正好是接收端 2.2 的倒数。暗部同样用直线段（斜率 4.5）。结构上和 sRGB 是"一个套路"。

## 6.7 BT.1886：把显示端也钉死

上面说的都是"内容怎么编码"。可如果每台显示器自己的 EOTF 都不一样，同一段内容放出来岂不是各不相同？于是需要一份**显示端**标准。

**BT.1886** 就是为此制定的：它规定了 HDTV 显示器的 EOTF，**接近纯 γ 2.4**，并且把屏幕的黑位和峰值亮度也纳入公式（而不是假设完美的 0 到 1）。

关键前提是：**BT.1886 假定你在暗室（家庭影院）观看，屏幕黑位接近 0。** 这个假设非常重要，因为它是"2.2 还是 2.4"那场争论的起点。

## 6.8 2.2 还是 2.4：一场关于环境光的争论

同样一条幂函数，为什么有人说 2.2、有人说 2.4？因为**观看环境不一样**。

- **暗室（家庭影院）**：环境光几乎没有，黑位可以压得很低。此时用稍陡的 **2.4** 能拉开暗部对比，黑更深、画面更"通透"，这就是 BT.1886 的选择。
- **明亮环境（办公、PC、客厅白天）**：环境光会"兜底"照亮屏幕，把黑位抬高，暗部被"洗白"。这时若还用 2.4，画面会显得**过暗、细节闷**；用稍缓的 **2.2** 更合适。

所以这不是"谁对谁错"，而是**"给什么环境用"**：PC 传统偏 2.2，影院偏 2.4。sRGB 名义上也是 2.2 阵营。

![图 06-4　BT.1886（≈γ2.4）与 Gamma 2.2 对比：差在观看环境与黑位](图片/06/f4_gamma_24.png)

$L_b$ 是 BT.1886 公式中的参数，代表显示器的黑位亮度 (Black Level Luminance)，即当输入码值为 0 时，屏幕发出的光。单位是 nit (cd/m²)。 

- $L_b = 0$：理想显示器，黑位完全为 0（比如理想的 OLED）。 
- $L_b = 0.5$ nit：实际显示器，黑位不是完全 0，而是 0.5 尼特。这是传统 LCD 或环境光反射造成的“底黑”（黑位抬高）现象。

BT.1886 的公式包含 $L_b$ 和 $L_w$（峰值白亮度），其数学表达式（通常用的简化形式）是： 

$$ L = a (V + b)^{\gamma} $$

其中： 

$a = \left(L_W^{1/\gamma} - L_B^{1/\gamma}\right)^{\gamma}$

$b = \frac{L_B^{1/\gamma}}{L_W^{1/\gamma} - L_B^{1/\gamma}}$

其中，$V$ 是输入码值（0 到 1）；$L_W$ 是峰值白亮度；$L_B$ 是黑位亮度（也就是图中的 $L_b$）；
$\gamma$ 是 Gamma 值（图中取 2.4），当 $L_b = 0$ 时，公式退化为纯幂函数；
$L = L_W \cdot V^{\gamma}$，黑位从 0 开始。 当 $L_b = 0.5$ 时，公式中的常数 $b$ 会把整个暗部曲线“抬起来”，使得 $V=0$ 时，亮度 = $0.5$ nit。

如果不考虑物理黑位，直接用纯 Gamma 2.4（橙线），那么在实际黑位是 0.5 nit 的屏幕（比如 LCD）上，按纯 Gamma 2.4 算出来的暗部信号（比如 V=0.1），可能要求屏幕发出 0.01 nit 的光，但屏幕根本做不到（它最低只能到 0.5 nit），这会导致暗部细节全部死黑一片。 BT.1886 引入 $L_b = 0.5$ 的作用就是，既然屏幕黑不下去，那就把暗部整体抬亮。这样一来，暗部细节能在这种屏幕上显示出来，防止暗部死黑。代价就是暗室的绝对对比度降低，看起来没那么“通透”了。


## 6.9 解码链错位会怎样

如果编码用的是一条曲线、显示用的是另一条，画面就会"走样"：

| 内容编码 | 显示端 EOTF | 结果 |
|---|---|---|
| 2.2 | 2.2（正确） | 正常 |
| 2.2 | 偏小（如 1.8） | **发灰**，黑不够黑、像蒙了层雾 |
| 2.2 | 偏大（如 2.6） | **发暗**，暗部细节被压死 |
| 2.4 | 2.2 | 略发灰（暗部被抬亮） |

这就是为什么"同一张图在两台显示器上，一台发灰一台正常"绝不只是"面板好坏"的问题，很可能是**链路上 Gamma 没对齐**。

## 6.10 一句话总结 SDR 的"约定"

到这里可以给 SDR 下个总账：**SDR 整条链路都是"相对、约定俗成"的。** 它假定显示白点大致在 100 nit（nit 即 cd/m²，二者等价）附近，EOTF 固定为约 2.2（或影院 2.4），色域锁定在 sRGB/BT.709。所有这些"约定"，共同把 SDR 的亮度上限和色彩范围都框死在一个小盒子里——这正是 HDR 要打破的（见第 7 章）。

## 本章小结

- **码值 ≠ 亮度**：像素值 128 对应的光大约是最大亮度的两成多，而非一半。
- **OETF 是光→码值（打包，采集端）**，**EOTF 是码值→光（解包，显示端）**，方向不能混。
- **Gamma 源自 CRT 的电压-亮度非线性**（γ≈2.2），1/2.2 的编码是为了抵消它，属于历史副产品。
- **非线性编码更省位深**：把码值向人眼敏感的暗部倾斜，8 位也能大致看不出色带。
- **sRGB 是分段 EOTF**：暗部走直线，亮部约 2.4 次方，整体等效约 2.2。
- **BT.709 定义 OETF**（指数 0.45），**BT.1886 定义显示 EOTF**（接近纯 γ 2.4，假定暗室）。
- **2.2 vs 2.4 取决于观看环境**：亮环境偏 2.2，暗室偏 2.4；链路错位会导致发灰或发暗。

## 常见误区与自测

1. **误区：以为 Gamma 只是"亮度调节"。** 它不是调亮暗的旋钮，而是码值与光之间固定的换算曲线；乱调会破坏整条链路。
2. **误区：把 OETF 和 EOTF 混着用。** 一个在采集端、一个在显示端，用反了画面必然失真。
3. **自测**：一张按 gamma 2.2 编码的图，放到一台 EOTF 偏 1.8 的屏幕上，看起来会？（答：发灰。）
4. **自测**：为什么 Gamma 编码能"省位深"？（答：把码值优先分给人眼敏感的暗部。）
