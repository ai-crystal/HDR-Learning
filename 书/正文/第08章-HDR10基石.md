# 第 08 章 HDR10：开放标准的基石

这一章我们要搞懂 HDR 世界里最"基础款"、却也最重要的一员——HDR10。你可能在电视、显示器、播放器、游戏里到处看到"HDR10"这个字眼，它几乎就是 HDR 的代名词。我们会先弄明白 HDR10 到底由哪几样东西拼成，再重点研究它的"元数据（metadata）"是什么、为什么重要，最后看清它最大的短板：整部片子只能用一套参数。理解了 HDR10，HDR10+ 和 Dolby Vision 就好懂了。

## 8.1 为什么需要一个"通用语"

想象一下，全世界有几百家电视厂、几十家电影公司、十几家游戏引擎、还有显卡厂、线材厂、流媒体平台……如果每家都自己发明一套"HDR 规则"，那结果必然是：这台电视放不出那部片的 HDR，那条线的信号又和另一台播放器对不上。这套系统根本转不起来。

所以 HDR 要落地，先得有人定一个**大家都遵守的"通用语"**。它不需要最先进，但必须满足三个条件：

1. **开放、免费**：谁都能实现，不用交授权费。
2. **简单、够用**：规则别太复杂，厂商容易做对。
3. **向下兼容**：不支持 HDR 的老设备，至少还能正常显示普通画面。

HDR10 就是这样的"最小公约数"。

> **类比**：HDR10 像"普通话"。它不是最优雅的语言，做不到吟诗作对，但全国人民都能听懂，所以它成了默认选项。后面要讲的 Dolby Vision 和 HDR10+ 更像是"方言+专业术语"——表达更细腻，但得双方都会说才行。

## 8.2 HDR10 的三件套

HDR10 这个名字听起来像一个技术，其实是**三样东西的组合**。缺一样，就不是完整的 HDR10：

| 组成 | 内容 | 作用 |
|---|---|---|
| 亮度编码 | PQ（SMPTE ST 2084） | 规定"码值 ↔ 绝对亮度"的对应关系，范围到 10000 nit |
| 色深 | 10bit（每通道 1024 级） | 给 PQ 这条很陡的曲线提供足够多的"台阶" |
| 色彩容器 | BT.2020（Rec.2020） | 规定画面可以使用的色域"大画布" |

注意这里有个常见误解：**BT.2020 是"容器"，不是"能力"**。标准规定"HDR10 的画面用 BT.2020 这套色域坐标来描述颜色"，但不代表你的电视真能显示全部 BT.2020。绝大多数设备实际只能显示出其中一部分（大约相当于 DCI-P3 甚至更小的范围），剩下的靠显示器自己做映射。（见第 5 章、第 17 章）

至于 PQ 和 10bit，我们在第 7 章已经讲过 PQ 的原理，这里再强调一句它们为什么绑在一起：

- PQ 是一条**绝对式**曲线，码值 0 对应 0 nit、码值最大对应 10000 nit（cd/m²）。
- 它把码值大量分配给了暗部，暗部变化非常陡——用 8bit（256 级）去装，很容易出现一条条"色带"。
- 所以 PQ 配 10bit（1024 级），是"HDR 的起步配置"，这一点第 10 章还会展开。

```text
         HDR10 = PQ(亮度) + 10bit(精度) + BT.2020(色彩容器)
                    │             │              │
                    │             │              └─ 颜色能用多"广"的范围
                    │             └─ 每个像素有多少级台阶
                    └─ 每个码值对应多少 nit 的绝对亮度
```

## 8.3 元数据：给显示器的一张"说明书"

要理解 HDR10 的脾气，必须先搞懂**元数据（metadata）**。

元数据不是画面本身，而是**"关于画面的信息"**。它像随货物一起发的**装箱单**：箱子（像素数据）里装了多少、有多重、有什么注意事项，都写在单子上。显示器拿到这张单子，才知道该怎么"搬货"。

在 HDR 里，元数据主要回答这类问题：

- 这部片子**最亮的地方有多亮**（峰值亮度）？
- 大概是**整体多亮**（平均亮度）？
- 母版（原始剪辑）是用什么样的显示器做的？

有了这些信息，显示器才能决定：内容里 4000 nit 的高光，我这块只能到 600 nit 的屏，到底该怎么压下去才不丢细节、不发灰。这个"压"的过程叫**色调映射（tone mapping）**（见第 17 章）。

HDR10 用的是**静态元数据（static metadata）**——注意"静态"两个字，我们马上会看到它的含义和代价。

![图 08-2　静态元数据：整部影片共用一套参数（逐帧亮度时序 + 全片唯一一条映射曲线）](图片/08/f2_static_meta.png)

## 8.4 静态元数据之一：SMPTE ST 2086（母版显示器信息）

HDR10 静态元数据的第一块内容，来自标准 **SMPTE ST 2086**，全称大意是"母版显示色彩容积元数据"。

**母版显示器（mastering display）**是什么？简单说，就是剪辑师和调色师用来"定稿"的那台专业显示器。电影最终长什么样，是由人坐在这台显示器前一遍遍调出来的。所以这台显示器的能力，直接决定了这部片子的"天花板"。

ST 2086 就是在片子里写明：**"我这片子是按照一台什么样的显示器做出来的"**，具体记录三组信息：

1. **三原色（基色）的坐标**：红、绿、蓝三个基色在色度图上的位置 → 说明母版能覆盖多广的色域。
2. **白点的坐标**：画面的"白"定在哪个位置，HDR 通常用 D65（约 6500K 的日光白）。
3. **母版的亮度范围**：最亮能到多少 nit、最暗能到多少 nit（例如"1000 nit 母版""4000 nit 母版"这类说法）。

```text
SMPTE ST 2086 告诉显示器三件事：
  ①母版的三个"颜料"（RGB 基色）在哪 → 色域有多广
  ②母版的"白"在哪               → 白点漂不漂
  ③母版最亮/最暗到多少 nit      → 亮度天花板
```

为什么显示器需要知道这些？因为如果内容是在 4000 nit 母版上做的，而你的屏幕只能到 600 nit，那显示端就得知道"我离人家差了多远"，才能算出合理的压缩曲线。这就是"谁来做 tone mapping"的起点。

## 8.5 静态元数据之二：MaxCLL 与 MaxFALL

ST 2086 描述的是"制作环境"，接下来两位是描述"**这部片子本身有多亮**"的：

| 名称 | 全称含义 | 大白话 |
|---|---|---|
| **MaxCLL** | 最大内容亮度等级（Maximum Content Light Level） | 整部片子里**最亮的那一个像素**有多亮，单位 nit |
| **MaxFALL** | 最大帧平均亮度等级（Maximum Frame-Average Light Level） | 全片**"平均最亮的某一帧"**的平均亮度，单位 nit |

先用一个类比记住它俩的区别：

> **类比**：MaxCLL 像"整场演唱会里**最响的那一声尖叫**"；MaxFALL 像"整场演唱会里**平均最吵的那一分钟**"。前者描述极端峰值，后者描述"大面积亮起来"时的整体负担。

这两个数字为什么有用？

- **MaxCLL 高**（比如约 4000 nit）：说明片子里有很亮的高光，比如太阳、爆炸、灯光。显示器得留出余量，否则这些高光会被"削平"成一片白。
- **MaxFALL 高**（比如几百 nit）：说明片子有很多**大面积的明亮场景**（雪原、白天外景）。这时候对屏幕的持续输出能力要求更高。

为什么需要 MaxFALL，而不能只看峰值？因为物理上，**"小亮点冲到很亮"和"整个屏幕都亮到很亮"是两回事**。LCD 的分区背光、OLED 的自动亮度限制（ABL），都会在"大面积亮场"时被迫降低亮度。所以厂商用两个数字分别描述这两种情况。（详见第 11、12 章）

> **小提醒**：MaxCLL 和 MaxFALL 在很多片源里**并不是百分百可靠**——有些片子写得保守，有些干脆缺失，还有些设备根本不去读它。所以它们是"参考建议"，不是"铁律"。

## 8.6 这些参数怎么传给显示器：CTA-861.3

知道了元数据是什么，还要解决"怎么送过去"的问题，毕竟这些数据需要让显示器知道。

这就轮到 **CTA-861.3** 出场了。CTA 是美国消费技术协会，**CTA-861** 是 HDMI 接口上"怎么描述视频信号"的规范，而 **CTA-861.3** 是其中专门补充 HDR 静态元数据的那一部分扩展。

它的工作方式是：把上面那些数字（ST 2086 的基色/白点/亮度范围，以及 MaxCLL/MaxFALL）打包成一个**HDR 静态元数据信息帧（HDR Static Metadata InfoFrame）**，跟随视频信号一起，通过 HDMI 线从播放设备送到显示器。

```mermaid
flowchart LR
    A["片源/播放器<br/>（读到 ST 2086 + MaxCLL/MaxFALL）"] --> B["显卡/播放器<br/>打包成 InfoFrame"]
    B -->|"HDMI 线<br/>随视频信号发送"| C["显示器/电视<br/>解析元数据"]
    C --> D["得知：内容亮度范围 + 母版信息"]
    D --> E["做色调映射，决定怎么压高光"]
```

这里牵出一个非常实际的结论：**HDR10 的元数据要传起来，需要 HDMI 2.0a 及以上的接口或对应能力的 DisplayPort（DP）**。更早的 HDMI 1.4 虽然也能跑 4K，但不支持这套 HDR 元数据的传输。所以老线、老口、老设备经常是"HDR 开不起来"的真凶之一。（见第 14、15 章）

HDMI 2.0a 于2015年4月发布，其最主要、也是几乎唯一的实质性更新，就是加入了 HDR 格式的传输能力。在此之前，HDMI 2.0 虽然具备了传输 4K@60Hz 信号所需的 18Gbps 带宽，但其规范中并没有定义如何让显示设备正确识别和呈现 HDR 内容。

另外，一个信息帧能装的位数有限，所以它记录的**是一组固定的数值，而不是一整段曲线**。这一点直接引出了 HDR10 的核心短板。

### 小谈 HDMI 与 DP

HDMI 由索尼、松下等影音大厂主导，2002年问世，目标是统一电视接口，取代老旧的 DVI 和 VGA。它采用封闭的授权模式，厂商使用需缴纳年费和版税。

DP 则由以戴尔、惠普、英伟达等为主的 PC 及芯片制造商联盟推动，2006年由 VESA（视频电子标准协会）标准化。它从诞生起就定位为免费、开放的标准，旨在取代 PC 领域内部的 DVI 和 VGA。

对于带宽与性能，DP 通常领先，HDMI 紧追。在相近的代际中，DP 的带宽上限通常更高。例如，DP 2.1 的最高带宽可达 80 Gbps，而 HDMI 2.1 为 48 Gbps。这使 DP 能更轻松地驱动超高分辨率和高刷新率的组合，例如 DP 2.1 可支持 16K@60Hz 或 8K@120Hz，而 HDMI 2.1 对应为 8K@60Hz 或 4K@120Hz。不过，对于绝大多数日常应用（如 4K@60Hz 或 4K@120Hz 游戏），两者的主流版本（DP 1.4 与 HDMI 2.1）都能胜任。

DP 是免授权费的开放标准，而 HDMI 则需缴纳年费（据报道约 1.5万美元）以及按产品计算的版税（曾报道约为每台设备 4 到 15 美分，或每根线缆约 1.1 美元）。尽管有这笔成本，HDMI 凭借其在电视、游戏主机（如 PlayStation、Xbox）和投影仪上近乎 100% 的渗透率，建立起了 DP 难以撼动的庞大生态。


## 8.7 静态元数据的局限：一部电影只用一张曝光表

"静态"这两个字，就是 HDR10 的天花板所在。它意味着：

**整部电影（或整段视频），从头到尾只共用这一套参数。** 一个 MaxCLL、一个 MaxFALL、一套母版信息，管到底。

用相机打比方：这就像你拍一整部电影，**只用一张固定的曝光表**——开场那个烛光餐桌、中场那个夜晚街头、结尾那个正午沙漠，全都用同一个曝光设定。结果必然是：

- 为了让**夜晚暗场**不发灰，曝光要往暗压 → 但这样**白天的雪原**就会过曝、一片惨白。
- 为了让**阳光下的高光**保留细节，曝光要往亮提 → 但这样**夜晚场景**就会被抬灰，本该纯黑的地方变成灰蒙蒙。

这就是**静态元数据的根本矛盾**：一部片子里，"暗场"和"亮场"往往需要不同的映射策略，而 HDR10 只给了一套。于是显示器只能做一个"折中妥协"——两端都照顾一点，两端都不完美。

```text
静态元数据（HDR10）：一部电影 = 一张曝光表

  暗场镜头        中等亮度场景       高光爆闪镜头
  ─────────────────────────────────────────────
  ↑ 需要"压暗"                    ↑ 需要"提亮"
        └──── 但只有一套参数，只能折中 ────┘
```

> **类比**：HDR10 像"整部电影只用一张曝光表"；而接下来要讲的动态元数据，则是"每一幕、甚至每一帧都换一张曝光表"。这个差别，正是 HDR10+ 和 Dolby Vision 存在的理由。

不过别急着看轻 HDR10。它的局限换来了巨大的好处：**简单、开放、兼容性最好**。只要设备"支持 HDR"，基本就一定支持 HDR10。这使它成为 HDR 世界里名副其实的**基石**和**最低门槛**。

## 本章小结

- **HDR10 是 HDR 的"通用语"**：开放、免费、向下兼容，是几乎所有 HDR 设备的最低门槛。
- **HDR10 = 三件套**：PQ（SMPTE ST 2084，绝对亮度，到 10000 nit）+ 10bit 色深 + BT.2020 色域容器。
- **BT.2020 只是容器**，不代表设备真能显示全部 BT.2020。
- **静态元数据有两块**：
  - **SMPTE ST 2086**：描述母版显示器的基色、白点、亮度范围。
  - **MaxCLL / MaxFALL**：分别描述"全片最亮像素"和"最亮帧的平均亮度"。
- **CTA-861.3** 是 HDMI 上承载这些静态元数据的规范，需要 HDMI 2.0a 及以上接口。
- **静态元数据的核心局限**：一部片只有一套参数，暗场和亮场难以两全，显示器只能折中。
- **HDR10 的地位**：最通用、最基础，但不一定最精细——精细交给 HDR10+ 和 Dolby Vision。

## 常见误区与自测

1. **误区：HDR10 和 DisplayHDR 是一回事。**
   不是。HDR10 是**内容格式标准**（讲画面怎么编码、怎么带元数据）；DisplayHDR 是 **VESA 的显示器认证**（讲一块屏幕达到什么硬指标）。一个说"片子"，一个说"屏幕"。（详见第 13 章）

2. **误区：片源带了静态元数据，显示器就一定会用。**
   很多设备会**直接忽略**静态元数据，按自己的固定曲线做映射——尤其是不少电视和显示器。所以"有元数据"不等于"用上了元数据"。

3. **自测：** 如果一部电影既有夜晚暗场、又有正午雪原，HDR10 的静态元数据为什么两头难顾？
   提示：因为全片只有**一套** MaxCLL/MaxFALL 和母版参数，无法为不同场景分别调整映射策略。

4. **自测：** 为什么 HDR10 要配 10bit，而不能用 8bit？
   提示：PQ 曲线暗部极陡，8bit 的台阶太粗，会导致暗部出现明显**色带（banding）**。
